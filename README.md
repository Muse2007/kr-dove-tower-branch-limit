# 四级塔双分支限制（Kingdom Rush Dove 版插件）

> 让 Dove 版的四级塔回到前三代原版的「两个分支」手感：**每个塔系，一局游戏内最多选用 2 种四级塔。**

开发环境：本体 `5.6.12`（`id = "2.0.8.4"`）。
只挂钩子、不改本体任何文件、不写存档。

---

## 一、它做什么

原版前三代里，三级塔升四级时只有两个分支可选。Dove 版把三代（以及四代、五代与 KR Genesis 移植关卡）的防御塔整合到了一起，同一个塔系下的四级分支数量变成了：

| 塔系 | 四级分支数量 |
| --- | --- |
| 箭塔 `archer_towers` | 18 |
| 法塔 `mage_towers` | 22 |
| 炮塔 `engineer_towers` | 18 |
| 兵营 `barrack_towers` | 24 |
| **合计** | **82** |

一座三级塔点开后摊出十几个分支，选择压力全无。本插件给每个塔系加一条**本局限额**：

- 每个塔系一局最多选用 **2 种**四级塔（数量可配）。
- 用满之后，该塔系**其余分支显示为本体的锁定图标**，不能再升级上去。
- **已选中的那 2 种仍可继续建造**——想造几座游侠就造几座，和原版一样。
- 四个塔系**各自独立计数**，箭塔用满不影响法塔 / 炮塔 / 兵营。

### 效果示例（箭塔，上限 2）

| 局面 | 塔菜单表现 |
| --- | --- |
| 场上没有四级箭塔 | 18 个分支全部可选 |
| 场上有 1 座游侠 | 仍然全部可选（还没用满 2 种） |
| 有游侠 + 火枪 | 十字弩、图腾、矮人…… 全部锁定；游侠 / 火枪仍可选 |
| 卖掉火枪（`ever` 模式，默认） | 依旧锁定——本局已经选过它了 |
| 卖掉火枪（`current` 模式） | 其它分支重新解锁 |

## 二、安装

1. 下载本仓库（`Code` → `Download ZIP`，或 `git clone`）。
2. 把 `tower_branch_limit` **整个文件夹**放进存档目录下的 `plugins/`：

   ```
   %APPDATA%\LOVE\kingdom_rush_dove\plugins\tower_branch_limit\
   ```

   （Windows 下把 `%APPDATA%` 展开即可；也可以在游戏里的插件管理器点「打开插件目录」。）

3. 确认 `plugins/plugin_main_config.lua` 中 `enabled = true`（总开关）。
4. **重启游戏**。启动后可在插件管理器的「玩法」分类里看到它。

卸载：在插件管理器里关掉，或直接删掉 `plugins/tower_branch_limit` 文件夹。

## 三、配置

在插件管理器中选中本插件，点「配置」：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `max_branches_per_family` | `2` | 每个塔系最多可选的四级塔**种类数**。填 `0` 或负数 = 完全不限制（等于关掉本功能） |
| `lock_mode` | `"ever"` | `ever`：本局建造过就算占用，卖塔不解锁其它分支<br>`current`：只算场上现存的种类，卖掉后其它分支重新解锁 |
| `lock_chosen_too` | `false` | `false`：只锁没选过的种类，已选的可以继续造<br>`true`：用满后连已选的也锁，该塔系不能再造任何四级塔 |

改完点「应用」即可**热生效**（插件实现了 `on_config_change`），不用重启游戏。
把 `max_branches_per_family` 设成 `0` 就能随时把这个功能关掉。

## 四、实现原理

只用了三个钩子，没有替换任何本体函数：

| 钩子 | 作用 |
| --- | --- |
| `TowerMenu.show` | 打开塔菜单前，把当前该锁的分支**临时**接在 `store.level.locked_towers` 末尾——本体自己就会把它们画成锁定图标；菜单构建结束（**含中途报错**）立刻还原，绝不把临时锁定留在关卡数据里 |
| `TowerMenu.button_callback` | 记录玩家最终选中的分支（`ever` 模式的依据）；同时拦截「菜单打开后塔系才被用满」造成的越权升级，并刷新菜单 |
| `simulation.do_tick` | 兜底重挂：`TowerMenu` 是全局类，一旦被重新定义就自动重新挂上钩子 |

判定依据：

- 塔系来自 `kr1.game_settings` 的 `GS.archer_towers / mage_towers / engineer_towers / barrack_towers`，
  下标 `>= 4` 的即四级塔。列表是**每次现取**的，所以**别的插件新增的四级塔也会被统计进来**
  （例如「狙击高台」「四代法师塔」这类往 `GS.*_towers` 里追加塔的插件）。
- 只处理「初级塔升到三级、准备挑四级分支」这一档菜单；一 / 二级塔菜单、四级塔自己的技能菜单不受影响。
- 本局记录挂在 `store.ephemeral` 上，换关 / 重开会自动清空。

## 五、兼容性与注意事项

- **不改本体文件、不写存档**：所有逻辑都在运行时通过钩子完成。
- 与其它插件**不冲突**：本插件只在自己的钩子里读数据、临时改动画面的锁定表，不会占用或替换共有接口。
- `ever` 模式的历史记录按塔系隔离，各塔系之间不会互相串味。
- **不影响 F1 一键造塔面板和补丁的「随机塔模式」**（有意保持原样）：但它们造出来的四级塔
  仍会被计入「本局已选用的分支」；随机塔模式的下一个分支是随机的，不受本插件约束。
- 无尽模式同样生效（走的是同一套塔菜单）。
- 若用无尽模式存档读档继续，`ever` 的历史记录会随 `store.ephemeral` 一起清空，
  此时按场上现存的四级塔重新计算。

### 目录结构

```

│   └── README.md                 #   游戏内插件详情页显示的内容
└── tools/test/                   # 离线逻辑测试
    ├── run.py
    ├── test.lua
    └── README.md
```

### 怎么跑测试

本体没有独立的 Lua 解释器，但自带 `lua51.dll`。测试脚本用 Python + ctypes 起一个真实的
Lua 状态，桩掉游戏外壳（`TowerMenu` / `simulation` / `game` / `GS`），只测插件自身的逻辑。

```bash
python tools/test/run.py --dll "<游戏目录>\lua51.dll"
```

想顺便验证插件对**本体真实 `hook_utils`** 的用法（责任链、`auto_table`、优先级、`UNHOOK`）：

```bash
python tools/test/run.py --dll "<游戏目录>\lua51.dll" \
    --real-hookutils "<游戏目录>\plugin\all\hook_utils.lua"
```

两种模式各 **49 项断言**，覆盖：上限计数、塔系隔离、`ever` / `current` 两种模式、`lock_chosen_too`、
上限可配（0 / 1 / 2）、菜单报错时的还原、选中分支的记账、越权升级拦截、一 / 二级塔与四级塔菜单不受影响、
新一局重置、`unload` 撤销全部钩子。详见 [`tools/test/README.md`](tools/test/README.md)。
